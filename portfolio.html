fixLinux 主线 · torvalds tree874611d193f2

mm/page_alloc · NUMA 内存回收 · sysctl

  • 问题：在 NUMA 架构上，读取内存相关 sysctl 参数会意外将节点的回收阈值清零——一个没有任何写入操作的"纯读"路径，触发了 NUMA min ratio 的重置。
  • 现象：多核 NUMA 服务器的内存回收出现抖动，水位判断失真，回收行为反复横跳，生产环境稳定性受损。
  • 修复：收敛 sysctl 处理逻辑，仅写操作更新 NUMA min ratio；读路径不再触碰任何全局状态。
  • 状态：代码已合入 Linux 主线（torvalds tree），随主线发布进入所有发行版。

平台与系统工程项目

基于 eBPF 与内核模块的分布式底层可观测性平台与诊断工具箱

eBPF (libbpf/BCC) · Linux Kernel Module · C/C++ · gRPC · Protobuf · MySQL

面向大规模服务器集群的低开销、无侵入系统级可观测平台，解决微服务场景长尾延迟与内核态异常难以排查的问题。

  • 独立开发多款内核追踪工具：调度延迟统计、进程生命周期追踪、VFS 文件操作监控、Slab 内存统计、慢 IO 分析、Off-CPU 阻塞分析、KVM 虚拟化卡顿观测。
  • 内核态聚合：基于 BPF Map 在内核态构建延迟直方图，直接输出 P90 / P99 尾部延迟指标，建立云电脑卡顿基线。
  • 网络观测：网络子系统 eBPF 无侵入埋点，PERCPU_ARRAY Map 在内核态完成收发包指标聚合，实现高精度网络监控。
  • 开销纪律：探针整体运行开销控制在 2% 以内——这是平台的第一设计约束。
  • 验证方法：stress-ng / iperf3 构造 CPU 抢占、网络拥塞、IO 瓶颈等高负载场景，结合 perf 完成探针开销与指标准确性验证。

基于 eBPF / Netlink 的智能网络观测与 AI 自动化诊断系统

Netlink · eBPF · TCP/IP · C/C++ · D-Bus · RAG / LLM

针对分布式与边缘设备的复杂网络连通性故障、长尾延迟问题，开发内核侧网络诊断守护进程，实现网络异常自动化根因分析。

  • 免旁路采集：通过 INET_DIAG Netlink 直接与内核交互，采集 Socket 级 TCP 丢包、重传、连接状态机指标，规避频繁调用系统命令的开销。
  • 进程级归因：kprobe 实现五元组到进程 PID 的映射，内核态聚合单进程 / 单链路的 PPS、Bps 流量数据。
  • 故障注入校准：TC / Netem 完成丢包、延迟、抖动注入，模拟弱网环境，校验诊断模块的指标统计准确性。
  • AI 闭环：构建「内核指标采集 → RAG 大模型分析 → 诊断报告输出」闭环；D-Bus 监听底层网络突变事件送入私有大模型做 RAG 推理，自动输出标准化网络诊断报告，完成故障自动化溯源。
